## Intended product

Qwen3-30B-A3B-family reasoning model, one shared serving endpoint, authorised
offensive-first learning followed by defensive detection/correction and independent
retest. Verified provenance-tagged experience feeds Loop A strategy/knowledge
changes and Loop B actual weight updates. Candidate SFT generations require
unseen evaluation, canaries, registry lineage, human promotion and rollback.
GRPO/population/cooperation follow a demonstrated SFT gain.

All six domains remain cumulative: web, Linux, Windows, AD, cloud and mobile.
Difficulty progresses from mapping through seeded weaknesses, multi-step tasks,
realistic constraints and withheld variants. Activation is resource-aware;
multi-host AD topology must fit concurrently. A curriculum manifest does not
establish an available target environment. Cloud emulation is distinct from
provider semantics. Mobile begins with owned Android apps; later iOS app-level
scope is retained. Targets: working fine-tuned model 15 January 2027; six-domain
product 30 June 2027. These are targets, not demonstrated delivery feasibility.

## Current implementation and limits

Implemented offline: schemas/configuration, serving preparation, narrow detection
verification and process isolation, Round-18 evaluation fixes/exclusions, rental
lifecycle instrumentation, training/reload preparation, evidence bundles, symbolic
reference and real HTTP authorization-boundary lab, bounded iterative lab process
and SSH client, defensive patch/retest and development trajectory export.

The real target is a deliberately small Python HTTP application with SQLite audit.
It is not DVWA/Juice Shop, arbitrary exploitation, a general agent platform or
six-domain coverage. Response and audit checks share a trusted lab controller.
Qwen execution, GB10 training/deployment, physical isolation and recurring weight
improvement remain unexecuted. Broad domain services, MAP-Elites, GRPO, sealed
promotion, recovery and mature curriculum controllers are not completed.

The long reference profile includes real benign HTTP background activity; it
measures one noisy task shape, not diverse long attack chains. Training logs must
show actual token lengths and truncation. Repeated-context stress is opt-in and
cannot be counted as additional verified wins or skill diversity.
